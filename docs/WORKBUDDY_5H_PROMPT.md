# 绘梨衣 2.1.1：精简、iOS 27.2 与高刷体验，五小时开发指令

本轮目标：让原生聊天 App 更精简、更可靠、更跟手。优先消除确定的问题，再做有价值的小改进。主验收系统为用户的 iOS 27.2，设备型号与 ProMotion 能力需实测记录，不能用模拟器或配置开关冒充真机验收。此任务是约五小时有效工作量，不保证 WorkBuddy 单次会话能连续运行五小时；遇到时限写交接记录后续跑。

## 可以整段复制的总指令

请接手本次 Erii 2.1.1 源码，从底层审查并继续精简和优化。先阅读 docs/RELEASE_2.1.1.md、docs/PERFORMANCE_ACCEPTANCE.md、docs/CLEANUP_MANIFEST.json 和本文件，然后检查代码。保留已完成的修复，不用旧版本覆盖，不重建整个项目，不把旧的功能矩阵当作实际完成证据。

如已安装 erii-ios-quality 技能，请使用它；否则直接读取项目内 .codebuddy/skills/erii-ios-quality/SKILL.md 执行相同流程。WorkBuddy 桌面版可用“专家·技能·连接器 → 技能 → 添加技能 → 上传技能”导入随附技能 ZIP。项目级 .codebuddy/skills 路径来自 CodeBuddy Code 文档，桌面 WorkBuddy 是否自动发现要实际检查；不能因文件存在就宣称已安装。无需为了本任务安装一堆无关第三方技能。

本轮围绕“聊天的连续性”工作：打开能看到历史，输入立即响应，消息状态可信，失败可恢复，搜索找得回，图片不拖慢滚动，后台回来不丢位置。新增能力要服务于这些体验。角色是绘梨衣，保留已有小本子、记忆、约定、共读/学习等后端成果，但不要把未接完的几十个功能全部堆到主屏。

## 必须遵守的工程约束

1. 删除前证明无用。追踪调用、模块导出、路由、资源、反射、测试与兼容入口。尤其 app.security._tokens_match 被测试和兼容导入使用，不能因为模块内没调用就删除。不要删除有效功能去缩短代码或修测试。
2. 默认保留用户数据库；数据库操作先做包含 WAL 的一致备份，在副本验证迁移/恢复。本包没有修改原始数据库结构或记录。用户历史、记忆与私人配置不是“垃圾”。
3. 禁止将 .env、真实数据库、聊天正文、密钥或日志上传公开仓库。公开源码与私人运行数据分开打包。保留 bundle identifier，避免更新后无法访问原 Keychain/本地数据。
4. 不升级全部依赖，不为简单效果引入大型 UI 框架。系统能力优先，变更依赖要说明证据和必要性。
5. 不用常驻 120Hz Timer、CADisplayLink 空转或不可见动画骗取高刷新率。系统允许时滚动与转场以 120Hz 为目标；静止时节能，低电量和发热下尊重系统降频。
6. 所有验证分为：静态检查、后端测试、Xcode 编译、XCTest、模拟器、真机性能、自签安装、公网联调。只填实际做过的项，不能互相替代。
7. 自动执行合理的编辑、局部测试和打包。缺 SDK、Mac、签名或第三方凭据时记录阻碍，继续能做的任务；不要反复请求确认，也不要伪造执行结果。
8. 用 docs/WORK_LOG.md 记录实际完成、证据路径、下一步和剩余时间；每阶段写一次，不把重复自检和等待当作有效开发。

## 五小时工作安排

### 0:00—0:30：基线、证据与精简清单

- 确认当前源码版本，保留用户未提交更改，建立可回退的工作副本。
- 读取清理清单，确认旧安装包/relay 运行记录没有回流。检查 docs 中是否有失效路径、旧版本数字或无法执行的指令。
- 运行 python scripts/audit_source.py、python -m ruff check backend/app --select F401,F841、python -m pytest -q、python scripts/swift_lint.py。
- 记录 Mac/Xcode/SDK/模拟器和真机是否可用。Mac 上优先执行 scripts/ios_validate.sh，处理真正的 Swift 6 类型/并发错误；不能只看 tree-sitter 通过。
- 列“可直接删除 / 需验证后删除 / 不能删除”三类：未使用私有方法、重复序列化、无效 SQL、旧样例、生成资源、重复状态、嵌套导航、无意义延迟。每项写引用证据。

验收：基线可复现，原数据未变，改动有边界。不要把必要的角色历史字段或 SQLite 迁移当成无用代码。

### 0:30—1:30：渲染与图片性能

- 检查本包新的 MediaStore actor、DecodedImage、MessageImageView：图片下采样是否真正离开主线程，方向/透明度是否保留，缓存淘汰后能否加载，失败后能否重试，同一媒体的并发请求是否合并。
- 补充图片请求背压与取消策略，防止快速滚动产生大量在途下载。取消一个 cell 的等待不能让其他 cell 的共享请求失败；内存警告后过期任务不能持续填满缓存。
- 缓存要区分服务器与账户，登出/换服务器清理相应内容。NSCache 的成本上限是建议值，不是全 App 内存保证。
- 图片气泡保持尺寸稳定。保留本版列表 960px / 点击后 2560px 高清加载与失败重试，验证两种尺寸不能误命中同一缓存。继续补取消、原图需求与跨尺寸下载复用；不在列表里缓存全部原图。
- 外观图片处理继续改为后台 ImageIO 下采样。壁纸长边按像素而非 pt*屏幕倍率计算；头像单独设较小尺寸。壁纸模糊和亮度可缓存处理结果，避免滚动时重复 GPU 工作；滑杆更新可合并，最终状态必须保存。
- 保持输入框草稿与历史列表状态隔离。不要把 ChatRows 重新变成每次 body 都复制的 Array(enumerated())；不要每条消息创建 DateFormatter 或解码 UIImage。
- 检查新图片视图的 Swift 6 隔离和 Sendable 约束：DecodedImage 只允许不可变 CGImage，禁止为解决报错给整个对象图随意加 @unchecked Sendable。

验收：1000/10000 条记录、50 张图片下滚动；记录主线程栈、冷/热缓存内存与重复下载次数。没有真机就完成可运行的测试和采集流程，标记性能结果待测。

### 1:30—2:20：聊天状态与响应速度

- 冷启动本地历史优先，健康探测、模型配置和主动消息不能串行阻塞进入聊天。用户开始输入后迟到的恢复请求不能覆盖当前消息或草稿。
- 队列持久化保证发送前写入 stable request_id 与 conversation_id，杀进程后按原 ID 重试。不要为了“防抖”延迟真正的消息入库；可以合并非关键状态快照。
- 当前 JSON 快照对长聊天会反复编码。先测 10000 条快照开销，再选择分会话快照/增量日志/SQLite。迁移必须向后兼容，不为少量记录提前做复杂数据库重构。
- 连发和媒体上传中断不堵住后续消息，失败有明确状态；同一逻辑消息重试不得重复生成。测试响应丢失、上游超时、后台切换、重复点击。
- 同步以 server_id/request_id/游标对账，删除同步不复活；分页不能跳过后续页。删除、收藏和编辑的变化要考虑已经同步到末尾的设备。
- 引用消息必须真正传到模型上下文，并区分引用内容与用户新陈述；不要把引文自动记成用户事实。
- 清理历史和切会话要处理在途任务；新会话的回复不能写回旧会话。队列与页面不要依赖全局可变单例。

验收：连续十条发送、部分失败、重启、双端同步四类回归。UI 滚动与输入不受网络等待影响，模型延迟单独报告。

### 2:20—3:10：iOS 27.2 原生体验

- 用含 iOS 27.2 SDK 的 Xcode 编译，记录版本与 build。保留 iOS 17 兼容路径，iOS 18+ 滚动观测走官方 API。
- 验证 ChatBottomObserver 的底部阈值、键盘开合、消息增加/删除、分页插入、快速返回；只有用户位于底部才跟随新消息，上翻阅读不被抢位置。
- 所有主页面只有一个 NavigationStack。设置通过 sheet 展示时由 sheet 提供栈，通过“我”push 时复用现有栈；检查返回手势和关闭按钮。
- 新 SDK 的系统导航、Tab、sheet 按原生设计运行，避免全局 UITabBarAppearance 覆盖和多层自制模糊。自定义玻璃只用已核对官方文档的 API，并写 availability 降级。
- 布局遵守安全区和动态键盘；不写死 iPhone 屏幕高度，不遮住底部输入框。适配 Dynamic Type、VoiceOver、减少动态效果、提高对比度和减少透明度。
- 标注准确状态：服务端未完成时不能显示“已送达/已读”；配置成功不等于连接成功；本地未联机不显示“在线”。不向用户展示无意义内部模型字段。
- Face ID 检查冷启动和后台锁定流程。已有 usage description 不等于鉴权正确；无法验证身份时不能默默放行私人聊天。

验收：真机中文输入法、长文本、复制/引用/删除、长按、图片预览、键盘与页面返回；没有闪黑、布局跳动、重复导航栏或点击无响应。

### 3:10—3:55：全局高刷与能耗验收

- 阅读 docs/PERFORMANCE_ACCEPTANCE.md 和技能的 acceptance.md。先建立基线，再优化 trace 中最重的两三个热点。
- 使用 Release 真机，记录低电量模式、限制帧速率和温度。120Hz 的预算约 8.33ms，按系统实际目标帧间隔判断错过帧；不能将主动降到 80/60Hz 等同于 App 卡顿。
- 测聊天快速滚动、图片首次出现、键盘进出、Tab 切换、sheet、长按菜单和全屏预览。目标工程预算：输入回显 P95 <50ms，已有本地历史首屏 <1s，滚动 hitch time ratio <5ms/s；这些是目标，未采集不能填“通过”。
- 每种场景至少三轮，记录数据量、帧间隔尾部、卡顿总时长、内存峰值、主线程热点、后台唤醒。平均 FPS 不能代替卡顿指标。
- 静止页面不需要 120 次每秒刷新。所有循环动画/任务按可见性、后台、减少动态效果停止；音频进度不需要 120Hz；不得轮询模型和连接状态来维持“在线”。
- 不承诺“永远全局 120 帧”。交付的是支持 ProMotion、有性能证据、对系统节能兼容的 App。

验收：保留 Instruments trace/xcresult 或明确阻塞；不能用一段打印“120”的脚本充当帧率仪表。

### 3:55—4:30：产品完整性与小范围增强

- 清理无效入口和重复说明。聊天主屏保留高频操作，小本子承载记忆/约定/回忆，“我”承载连接与外观；低频功能使用渐进展示。
- 优先补用户看得见的断点：图片错误重试、语音朗读失败提示、搜索结果准确定位、草稿恢复、未读数量、收藏反馈。一次选两三项做完整闭环。
- 搜索先按服务端 ID 定位，不按重复正文猜测。结果不在本地窗口时应加载对应位置并高亮，不能悄悄滚到另一条相同文本。
- 日记、长期记忆和临时聊天继续保持来源与隐私边界；不要为了个性化把临时聊天混入备份、回忆或主动联系。
- 现有 36 项需求仍是长期计划，本轮不强求所有接口变成按钮。待实现的通话/桌宠/Widget 等给出真实能力状态，不用占位成功页面。

验收：新增项目必须有加载、空态、失败、重试与持久化，不扩大无效代码面积。

### 4:30—5:00：回归、清理、交接

- 跑相关回归与最终全量测试，修失败后再交付。不重复已通过的完整套件浪费剩余时间。
- 导出前运行 audit_source.py、ruff F401/F841、pytest、Swift 静态检查；Mac 环境运行构建/XCTest，真机性能另记。
- 对比原始数据、资源清单、API 行为和删除清单。若测试反证某个“未用”符号属于兼容契约，恢复它并明确重导出，不改弱测试。
- 清除缓存、DerivedData、旧 IPA、临时 trace 大文件和测试库。trace 可单独附件，别混进精简源码包。保留新源码、有效资源、最少必要文档、验证日志和技能源文件。
- 输出新完整源码包、可浏览器下载的交付入口、详细变更与当前限制、下一轮提示词。不要将旧 IPA 改名成新版本；有签名产物才另外标注实际构建版本。
- 本轮报告必须同时写出：删除了什么、为什么能删、代码新增了什么以及为什么值得新增、前后包体差异、通过的测试、没有验证的性能目标。

## 每阶段检查清单

- 数据：现有聊天/记忆没丢；失败操作可回滚；没有删除生产配置。
- 聊天：状态可恢复；消息顺序稳定；重试幂等；多端删除正确；草稿不被图片选择清空。
- 性能：body 无 IO；无无限媒体缓存；无每次输入全量列表复制；无假 120Hz 循环；主线程工作量有证据。
- 交互：只有一个导航栈；不抢滚动位置；大字体可读；失败可见且可重试。
- 安全：签名标识保留；模型 Key 不进客户端；临时会话不成为其他功能依据。
- 交付：构建与测试分开报告；真实设备成绩与计划分开；文档不和代码打架。
